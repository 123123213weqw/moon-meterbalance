# MeterBalance — 面向园区配电的分表对账与异常溯源

**应用对象**　学校、园区和楼宇的能源管理人员，以及负责接入分表数据的工程师。

**交付形式**　MoonBit 核心库、离线命令行、可追溯 JSON 报告和两类复核样本。[项目仓库](https://github.com/123123213weqw/moon-meterbalance)

## 问题与处理流程

总表与直接分表的差额可能来自未计量负载、测量误差、缺测或真实对账冲突。设施人员先定义总表、配电箱和支路的层级，以及各级合理的未计量用电上下界，再导入已按固定时间窗对齐的电量或区间平均功率。MeterBalance 输出每个窗口、每个节点的直接对账和子树结论。值班工程师可沿报告里的表计 ID、冲突区间和原始读数行号，决定补采哪张表，或先检查哪一段配电关系。

## 技术特点与相近方案

使用 64 位定点整数把 Wh、kWh、区间平均 kW 转为微瓦秒。算法从叶表向上收窄可行区间，检查整棵子树能否同时满足各级守恒约束。报告单独保留可行、已证不相容与数据不足三类结论，其中子树阻塞可沿下级证据定位。Emoncms 的输入处理覆盖数据记录、累加与功率换算，MoonFrame 提供表格读取与转换，MeterBalance 交付的是固定窗口上多层表计约束的可行性判断与行级证据。[Emoncms 输入处理](https://docs.openenergymonitor.org/emoncms/inputs.html) · [MoonFrame CSV 接口](https://mooncakes.io/assets/ihb2032/MoonFrame%400.5.2/io/csv.mbt.html)

## 演示与复核

公开 UCI 住宅数据的两个节选共 1,476 个一分钟窗。独立有理数程序逐窗核对 1,461 个完整窗的差额和来源行，并确认 15 个缺测窗保留为数据不足。三层样例复现了总表局部可行、纳入末端证据后出现冲突的场景。另用独立穷举程序核对 128 个窗口中 640 个子树的投影端点。克隆后运行 `python scripts/verify.py` 即可复核。当前审计约定为单根、单向有功计量树，并以输入误差区间和未计量负载边界为判定前提。[样本出处与复核方式](../examples/uci/SOURCES.md)
